Prefix sum

Store cumulative totals so a range can be evaluated by subtraction.

One boundary convention

Let prefix[i] be the sum of values before index i. Then prefix[0] = 0, and a list of n values has n + 1 prefix entries.

prefix[i + 1] = prefix[i] + nums[i]
sum over [left, right) = prefix[right] − prefix[left]

The left endpoint is included; the right endpoint is excluded. For an inclusive range [left, right], use prefix[right + 1] - prefix[left].

Advantage: O(1) sum queries after an O(n) build; negative values are allowed. Limitations: O(n) storage, and changing one input value can invalidate all later prefixes. A minimum or maximum cannot generally be recovered by subtracting two prefix values.

Build and query

Python
# Build: time O(n), extra space O(n)
# Each range query: time O(1), extra space O(1)
def build_prefix(nums: list[int]) -> list[int]:
    prefix = [0]
    for value in nums:
        prefix.append(prefix[-1] + value)
    return prefix


def range_sum(prefix: list[int], left: int, right: int) -> int:
    if not 0 <= left <= right < len(prefix):
        raise ValueError("Require 0 <= left <= right <= n")
    return prefix[right] - prefix[left]

The leading zero handles a range starting at index 0 without a special case. An empty range [i, i) has sum zero. A range query is subtraction; creating nums[left:right] would instead copy and scan the range.

Count subarrays with a target sum

If the current prefix is total, an earlier prefix must equal total - target because their difference is the subarray sum. Count all such earlier prefixes, then record the current one.

Python
# Expected time O(n): one prefix lookup per element
# Extra space O(n): counts of earlier prefix sums
def count_target_sums(nums: list[int], target: int) -> int:
    counts = {0: 1}
    total = 0
    answer = 0
    for value in nums:
        total += value
        answer += counts.get(total - target, 0)
        counts[total] = counts.get(total, 0) + 1
    return answer

{0: 1} counts the empty prefix. A frequency is needed because several earlier prefixes can have the same value. Query before inserting the current prefix so a target of zero does not count an empty subarray at every position.

Reading the complexity comments

n is the input length unless another size is defined. Extra space excludes the input and counts stored results when they are constructed. Recursion frames count as extra space. Costs assume bounded-size values and constant-time comparisons; dictionary and set costs are expected under ordinary hashing.
