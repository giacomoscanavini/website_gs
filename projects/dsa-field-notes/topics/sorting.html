Sorting

Build order by inserting, selecting, merging, exchanging, distributing, or partitioning.

What to compare

Stable means equal-key records keep their original order. In place means the main array is rearranged rather than replaced; recursion can still use extra memory. Here n is the number of values and b is the number of buckets.

Insertion, selection, bubble, and quicksort below change the input and return None. Merge and bucket sort return a new list. In ordinary Python code, nums.sort() changes the list, while sorted(nums) returns a new one; both are stable.

Sorting is preprocessing: include its cost in the full algorithm. Sorting by one key can also destroy the original order needed by another part of the task.

Insertion sort

Pattern: maintain a sorted prefix. Save the next value as key, shift larger prefix values one position right, and insert key into the gap.

Pros: simple, stable, and efficient on small or nearly sorted inputs. Cons: many shifts on reversed input. With I inversions, its work is O(n + I); in the worst case I is quadratic.

Python
# Time O(n^2) worst case, O(n) for already sorted input
# Extra space O(1)
def insertion_sort(nums: list[int]) -> None:
    for i in range(1, len(nums)):
        key = nums[i]
        j = i - 1
        while j >= 0 and nums[j] > key:
            nums[j + 1] = nums[j]
            j -= 1
        nums[j + 1] = key

Use > rather than >= to avoid moving equal values past one another. The prefix is sorted after each insertion, but those values are not necessarily in their final global positions yet.

Selection sort

Pattern: find the smallest remaining value and swap it into the next final position. Before pass i, positions before i are final.

Pros: at most n - 1 placement swaps. Cons: the remaining suffix must still be scanned on sorted input; ordinary swapping is not stable. For equal-key records [2a, 2b, 1], moving 1 to the front yields [1, 2b, 2a].

Python
# Time O(n^2) for every input order
# Extra space O(1)
def selection_sort(nums: list[int]) -> None:
    for i in range(len(nums) - 1):
        smallest = i
        for j in range(i + 1, len(nums)):
            if nums[j] < nums[smallest]:
                smallest = j
        nums[i], nums[smallest] = nums[smallest], nums[i]

Cost: the comparisons add up to (n - 1) + (n - 2) + ... + 1 = n(n - 1)/2.

Merge sort

Pattern: divide into halves, sort each half, then merge with one index per half. Append the smaller available value. Once one half is exhausted, append the rest of the other.

Pros: predictable O(n log n) time and stable ordering. Cons: this array version allocates slices and merged lists. The merge itself is linear; roughly log n split levels give the total time.

Python
# Time O(n log n): linear merging at each split level
# Extra space O(n) peak including slices and output, plus O(log n) frames
def merge_sort(nums: list[int]) -> list[int]:
    if len(nums) <= 1:
        return nums.copy()
    mid = len(nums) // 2
    left = merge_sort(nums[:mid])
    right = merge_sort(nums[mid:])
    result = []
    i = j = 0
    while i < len(left) and j < len(right):
        if left[i] <= right[j]:
            result.append(left[i])
            i += 1
        else:
            result.append(right[j])
            j += 1
    while i < len(left):
        result.append(left[i])
        i += 1
    while j < len(right):
        result.append(right[j])
        j += 1
    return result

Taking from the left on equality preserves stability. Slices across a single recursive path have geometrically decreasing lengths, so peak live storage is O(n), not O(n log n). The total amount allocated over the whole run can still be O(n log n).

Bubble sort

Pattern: exchange adjacent out-of-order values. After a left-to-right pass, the largest remaining value is at end, so shorten the next pass.

Pros: simple, stable, and stops early when a full pass makes no swaps. Cons: usually many comparisons and swaps; little reason to choose it over insertion sort for small inputs.

Python
# Time O(n^2) worst case, O(n) for already sorted input
# Extra space O(1)
def bubble_sort(nums: list[int]) -> None:
    for end in range(len(nums) - 1, 0, -1):
        swapped = False
        for j in range(end):
            if nums[j] > nums[j + 1]:
                nums[j], nums[j + 1] = nums[j + 1], nums[j]
                swapped = True
        if not swapped:
            break

The no-swap test belongs after a complete pass, not after a single ordered pair. Only strict inversions are swapped, preserving equal-key order.

Bucket sort

Pattern: map values into ordered ranges, sort inside each bucket, then concatenate buckets in range order. This version accepts values in [0, 1) and maps a value to int(value * b).

Pros: expected linear work when independent, roughly uniform inputs spread across b proportional to n buckets. Cons: the range and distribution matter; clustered values can put almost everything in one bucket. A value of 1 would map outside these buckets and is rejected.

Python
# Expected time O(n + b + n^2 / b) for independent uniform values
# Worst time O(n^2 + b), extra space O(n + b), b is the bucket count
def bucket_sort(nums: list[float], bucket_count: int | None = None) -> list[float]:
    b = max(1, len(nums)) if bucket_count is None else bucket_count
    if b < 1:
        raise ValueError("The bucket count must be positive")
    buckets = [[] for _ in range(b)]
    for value in nums:
        if not 0 <= value < 1:
            raise ValueError("Values must lie in [0, 1)")
        buckets[int(value * b)].append(value)
    result = []
    for bucket in buckets:
        for i in range(1, len(bucket)):
            key = bucket[i]
            j = i - 1
            while j >= 0 and bucket[j] > key:
                bucket[j + 1] = bucket[j]
                j -= 1
            bucket[j + 1] = key
        result.extend(bucket)
    return result

With bucket sizes m₀, m₁, ..., insertion sorting contributes O(Σ mᵢ²). Uniform independent inputs give expected time O(n + b + n²/b); setting b proportional to n makes this O(n). A fixed small bucket count does not guarantee linear scaling. This is bucket sort, not counting sort: a bucket can contain different values that still need sorting.

Quicksort

Pattern: partition around a pivot, put the pivot in its final position, and sort the two remaining intervals. This version chooses the last value as the pivot and uses inclusive bounds [lo, hi] inside its recursive calls.

During partition, nums[lo:i] contains values below the pivot. j scans the remaining non-pivot values. Swap a smaller value to i and advance i. Finally swap the pivot into i.

Pros: partitions the original array with little work per comparison and can be efficient with balanced splits. Cons: unstable; choosing the last value gives quadratic work on sorted, reversed, or all-equal inputs. Deep recursion can also exceed Python's recursion limit.

Python
# Time O(n log n) for balanced partitions, O(n^2) worst case
# Extra space O(log n) for balanced recursion, O(n) worst case
def quicksort(nums: list[int]) -> None:
    def partition(lo: int, hi: int) -> int:
        pivot = nums[hi]
        i = lo
        for j in range(lo, hi):
            if nums[j] < pivot:
                nums[i], nums[j] = nums[j], nums[i]
                i += 1
        nums[i], nums[hi] = nums[hi], nums[i]
        return i

    def sort(lo: int, hi: int) -> None:
        if lo >= hi:
            return
        p = partition(lo, hi)
        sort(lo, p - 1)
        sort(p + 1, hi)

    sort(0, len(nums) - 1)

A balanced split gives T(n) ≈ 2T(n/2) + O(n). Repeated splits of sizes 0 and n - 1 give T(n) = T(n - 1) + O(n) = O(n²). Random pivots reduce dependence on input order; three-way partitioning handles many equal keys more directly. Neither change is included in the simple implementation above.

Reading the complexity comments

n is the input length unless another size is defined. Extra space excludes the input and counts stored results when they are constructed. Recursion frames count as extra space. Costs assume bounded-size values and constant-time comparisons; dictionary and set costs are expected under ordinary hashing. The step viewer stores snapshots for illustration; that storage is not part of the displayed algorithm.
