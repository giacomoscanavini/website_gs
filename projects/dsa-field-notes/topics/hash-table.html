Dictionary or set?

A dictionary maps each key to a value. A set records whether a value is present. Hashing narrows where a key is stored; equality checks distinguish keys when hashes collide.

Need Python structure Common update
Membership only set() seen.add(value)
Frequency dict or Counter counts[value] = counts.get(value, 0) + 1
Earlier position dict seen[value] = index
Group equivalent items dict of lists Map a canonical key to its group
Reuse a subproblem result dict or @cache Map the full state to its answer

Advantage: expected constant-time lookup, insertion, and deletion with ordinary fixed-size keys. Limitations: extra memory, no sorted-key search, and worst-case linear operations under severe collisions. Hashing a new long string or tuple also takes work proportional to its size.

Python dict preserves insertion order, not sorted order. A set has no guaranteed iteration order. {} is an empty dictionary; an empty set is set(). Keys must be hashable: a tuple of integers works; a list does not.

Frequency counting

For each value, read its current count, using zero when absent, then add one. The number of dictionary entries is the number of distinct values, not the input length unless all values differ.

Python
# Expected time O(n): one hash-table update per value
# Extra space O(u): one entry per distinct value
def frequencies(nums: list[int]) -> dict[int, int]:
    counts = {}
    for value in nums:
        counts[value] = counts.get(value, 0) + 1
    return counts

Complement lookup

To find two values summing to a target, the partner needed for value is target - value. Check earlier values before storing the current one.

Python
# Expected time O(n): one lookup and at most one insert per value
# Extra space O(n): remember earlier values and their indices
def pair_unsorted(nums: list[int], target: int) -> tuple[int, int] | None:
    seen = {}
    for i, value in enumerate(nums):
        need = target - value
        if need in seen:
            return seen[need], i
        seen[value] = i
    return None

The input need not be sorted, and the returned positions are original indices. For [3, 3] with target 6, the first 3 is stored at index 0; the second finds it and returns (0, 1). Inserting before checking could reuse the same element.

Choose what a key should store

Store a count to count matches, the earliest index to maximize a distance, or the latest index to enforce a recent boundary. Overwriting a value is correct only when the older information is no longer needed. For grouping anagrams, a sorted-character tuple or a fixed-alphabet count tuple can identify the group; constructing that key is part of the cost.

Reading the complexity comments

n is the input length unless another size is defined. Extra space excludes the input and counts stored results when they are constructed. Recursion frames count as extra space. Costs assume bounded-size values and constant-time comparisons; dictionary and set costs are expected under ordinary hashing.
