Two pointers

Use two indices to scan, compare, or rewrite a sequence without restarting the search.

Common patterns

A pointer here is an index, not a special Python object. Decide what each index means before writing the loop.

Pattern Meaning of the indices Typical use
Opposite ends left and right bound the remaining choices Sorted pair sums, palindrome checks, reversing
Read and write read examines input; write marks the next output slot Remove values, move zeros, keep unique values
One index per sequence i and j track progress in different sequences Merge sorted data, check a subsequence
Slow and fast One advances once; the other advances twice Middle of a linked list, cycle detection

Advantage: often one pass and constant extra space. Limitation: every move needs a reason why discarded positions cannot help. Two indices alone do not make an algorithm linear.

Opposite ends: a pair in sorted data

For an ascending list, compare nums[left] + nums[right] with the target.

  1. If the sum is too small, increase left. Even the largest remaining partner was not enough for the old left value.
  2. If the sum is too large, decrease right. Even the smallest remaining partner was too much for the old right value.
  3. Return on equality. Stop when the indices meet: the pair must use different positions.
Python
# Time O(n): each pointer moves at most n times
# Extra space O(1)
def pair_sorted(nums: list[int], target: int) -> tuple[int, int] | None:
    left, right = 0, len(nums) - 1
    while left < right:
        total = nums[left] + nums[right]
        if total == target:
            return left, right
        if total < target:
            left += 1
        else:
            right -= 1
    return None

Cost: at least one boundary moves on each unsuccessful iteration; neither reverses direction. Sorting an unsorted input first adds O(n log n) time and changes its index positions. This function assumes the input is already sorted.

Read and write: keep a compact prefix

nums[:write] contains the values kept so far, in their original order. Read every element once. Copy a kept value to write, then advance write. A rejected value advances only read.

Python
# Time O(n): one read per element
# Extra space O(1): overwrite the original list
def compact(nums: list[int], remove: int) -> int:
    write = 0
    for read in range(len(nums)):
        if nums[read] != remove:
            nums[write] = nums[read]
            write += 1
    return write

The return value is a length, not a new list. Only the prefix up to that length is meaningful. Overwriting is safe because write never passes read. Taking nums[:length] afterward creates a new list and costs O(length) time and space.

Common mistakes

Moving both ends when only one is justified can skip a solution. Sorting can destroy original indices. Repeated pop(i) or insert(i, value) in the middle shifts later values and can turn a one-pass idea into quadratic work.

Reading the complexity comments

n is the input length unless another size is defined. Extra space excludes the input and counts stored results when they are constructed. Recursion frames count as extra space. Costs assume bounded-size values and constant-time comparisons; dictionary and set costs are expected under ordinary hashing.
