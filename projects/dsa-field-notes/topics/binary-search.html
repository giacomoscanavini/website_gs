Binary search

Halve a sorted search interval until a value or a boundary is located.

Three different questions

All three examples use an ascending list and a half-open interval [lo, hi). Set lo = 0, hi = len(nums), and continue while lo < hi. Never read nums[hi] just because hi is a boundary.

Search Return value When nothing qualifies
Find a value Any index with nums[i] == target -1
Lower boundary First index with nums[i] >= target n
Upper boundary First index with nums[i] > target n

Upper boundary is not the last matching index. It is the insertion position after all equal values. For [1, 2, 2, 2, 4, 6] and target 2, the lower boundary is 1, the upper boundary is 4, and the last matching index is 3.

Advantage: O(log n) comparisons and O(1) extra space. Limitations: data must be sorted or the tested condition must be monotonic. Preparing unsorted data costs time; inserting into a Python list is still O(n) after the position is found.

Find a value

On equality, return. If the middle value is too small, discard it and everything before it by setting lo = mid + 1. Otherwise set hi = mid, excluding the middle and everything after it from the remaining value search.

Python
# Time O(log n): halve the remaining interval each iteration
# Extra space O(1)
def find_value(nums: list[int], target: int) -> int:
    lo, hi = 0, len(nums)
    while lo < hi:
        mid = (lo + hi) // 2
        if nums[mid] == target:
            return mid
        if nums[mid] < target:
            lo = mid + 1
        else:
            hi = mid
    return -1

This returns one occurrence, not necessarily the first when duplicates exist. An empty input immediately returns -1.

Find the lower boundary

All indices before lo have values below the target. All indices at or after hi have values at least the target. The loop narrows the unclassified region between them.

If nums[mid] < target, move lo past mid. Otherwise move hi to mid: equality is a reason to continue searching left, not to return.

Python
# Time O(log n): halve the remaining interval each iteration
# Extra space O(1)
def lower_bound(nums: list[int], target: int) -> int:
    lo, hi = 0, len(nums)
    while lo < hi:
        mid = (lo + hi) // 2
        if nums[mid] < target:
            lo = mid + 1
        else:
            hi = mid
    return lo

Find the upper boundary

Change only the comparison: discard the left side when nums[mid] <= target. Equal values must lie before the answer, so search farther right.

Python
# Time O(log n): halve the remaining interval each iteration
# Extra space O(1)
def upper_bound(nums: list[int], target: int) -> int:
    lo, hi = 0, len(nums)
    while lo < hi:
        mid = (lo + hi) // 2
        if nums[mid] <= target:
            lo = mid + 1
        else:
            hi = mid
    return lo

Python's bisect_left and bisect_right implement the lower and upper insertion boundaries. For binary search on an answer, the condition must change only once, such as False, False, True, True. Search for the first feasible value. If one feasibility check costs C, total time is O(C log R) over an integer search range of size R.

Boundary mistakes

lo = mid may fail to shrink a two-position interval. Mixing an inclusive hi = n - 1 template with half-open update rules can skip positions. Boundary searches may return n; test the result before indexing. Sorting first is not part of the O(log n) search cost.

Reading the complexity comments

n is the input length unless another size is defined. Extra space excludes the input and counts stored results when they are constructed. Recursion frames count as extra space. Costs assume bounded-size values and constant-time comparisons; dictionary and set costs are expected under ordinary hashing. The step viewer stores snapshots for illustration; that storage is not part of the displayed algorithm.
