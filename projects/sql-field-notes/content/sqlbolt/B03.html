SQLBolt / Lesson 3

Text constraints and LIKE

LIKE patterns use % for zero or more characters and _ for exactly one character. Equality matches a complete value. NOT LIKE excludes matching non-NULL values.

Note. LIKE is case-insensitive in this SQLBolt environment. This is not a universal SQL rule: engine and collation matter. Pandas patterns below deliberately use case=False for LIKE; equality uses the capitalization shown in the examples.

01 · Toy Story titles

SQL 
SELECT * FROM movies WHERE title LIKE 'Toy Story%';
pandas 
result = movies.loc[movies['title'].str.contains(r'^Toy Story', case=False, na=False)].copy()

02 · Movies by John Lasseter

SQL 
SELECT * FROM movies WHERE director = 'John Lasseter';
pandas 
result = movies.loc[movies['director'].eq('John Lasseter')].copy()

03 · Movies by other directors

SQL 
SELECT title, director FROM movies WHERE director <> 'John Lasseter';
pandas 
mask = movies['director'].notna() & movies['director'].ne('John Lasseter')
result = movies.loc[mask, ['title', 'director']].copy()

04 · WALL- followed by one character

SQL 
SELECT * FROM movies WHERE title LIKE 'WALL-_';
pandas 
result = movies.loc[movies['title'].str.fullmatch(r'WALL-.', case=False, na=False)].copy()

The lesson’s WALL-* wording is implemented using the SQL single-character wildcard _. For an unrestricted suffix, use WALL-%.
