Separate structure, routing, and objective

The architecture guide distinguishes three choices: the structure of the data, the information-routing rule, and the prediction objective. Models can use the same loss while moving information in very different ways.

A sequence contains meaningful order. A graph specifies relations that are not generally a simple sequence. A vector or image can be compressed through a latent representation. The appropriate architecture encodes assumptions about which interactions should be easy to represent.

The source’s central question is how does information move? That question gives a more stable mental map than a list of model acronyms.

The source’s conceptual map

Family Routing mechanism Persistent or intermediate representation
RNN Reuse a state transition across time Hidden state
LSTM / GRU Gate the state update Cell/hidden state or one gated state
Encoder–decoder Encode a source, decode a target Context or source memory
Autoencoder Compress and reconstruct Latent code
Transformer Content-dependent token interaction Contextual token representations
GNN Pass messages along edges Node representations
GAT Learn weights over graph neighbors Attention-weighted node representations

There is no strict hierarchy in which each newer family replaces all earlier ones. The models express different inductive biases, and some solve different training objectives altogether.

Choose the architecture by the available relationships

For a streaming sequence, a recurrent state naturally carries information from the past. A bidirectional recurrent model uses future context too; that can be useful offline and invalid when future inputs are unavailable at prediction time.

For a long sequence with content-dependent interactions, attention offers direct access to allowed source positions. The cost of dense pairwise interactions grows with sequence length, so the routing benefit comes with a computational trade-off.

For relational data, a graph model uses the given neighborhood rather than flattening every entity into unrelated rows. Its usefulness depends on graph construction, edge direction, self-loops, and whether the split matches deployment.

An autoencoder is appropriate when reconstruction or a latent representation is the objective. If labels for a downstream task are available, good reconstruction does not automatically mean the representation is best for that task.

Roles can be combined

The guide gives LSTM autoencoders, temporal GNNs, graph Transformers, and encoders feeding relational models as examples of hybrids. These are not exceptions to the map: each component contributes a routing or representation role.

A residual connection and an LSTM cell path share an optimization theme: preserve a relatively direct route and learn modifications around it. Gates and attention both select information, but at different granularities. A gate scales state coordinates; attention assigns weights across candidate source representations.

Every autoencoder has an encoder, but a classifier’s encoder does not make it an autoencoder. Distinguishing architectural roles from training objectives prevents several common study confusions.

Complexity is not just parameter count

Two models with similar parameter counts can have very different computational structure. Recurrence has a sequential dependency chain. Dense attention has pairwise interactions and parallel training across positions. Graph models operate on the selected edges and can create a different batching problem for variable-size graphs.

The source asks for comparison under the same split and metric, including training time, inference cost, robustness, and data regime. The architecture should earn its complexity by improving the intended procedure rather than merely having greater expressiveness.

Step by step Derive receptive reach from repeated local information routing

Setting. Let AA be a nonnegative adjacency matrix describing allowed one-step messages between nn positions or nodes. Ignore nonlinearities for the first calculation so the support of information flow is easy to inspect. This is a structural derivation, not a claim that every allowed influence is learned or useful.

1 · Expand one and two propagation steps

For scalar input features xx , one step gives h(1)=Axh^{(1)}=Ax , with hi(1)=∑jAijxjh^{(1)}_i=\sum_jA_{ij}x_j . A second gives

A term AijAjkA_{ij}A_{jk} is nonzero only when information can travel from kk through jj to ii .

2 · Extend by induction

If h(L)=ALxh^{(L)}=A^Lx , then h(L+1)=Ah(L)=AL+1xh^{(L+1)}=Ah^{(L)}=A^{L+1}x . For an unweighted graph, (AL)ik(A^L)_{ik} counts walks of length LL from kk to ii . Including self-loops lets shorter paths be padded with “stay” steps, giving access within at most LL hops.

3 · Restore learned transformations

A local message-passing layer can transform and nonlinearly combine its inputs, but without an extra long-range connection its output still depends only on its allowed neighbors. Repeated composition expands the possible dependency set by another hop per layer. Cancellation, learned zero weights, or compression can make the actual dependence smaller than this structural bound.

4 · Compare recurrence and unrestricted attention

In a recurrent chain, an input at time kk reaches time TT through T−kT-k transitions. Dense attention permits a direct edge between any allowed pair in one layer, while causal or local masks remove edges. This changes dependency path length, not a guarantee of successful memory or reasoning.

5 · Keep computation separate from parameter sharing

Repeating the same recurrent cell for TT steps multiplies its compute and activation-storage needs but not the number of distinct cell parameters. Unrestricted attention has T2T^2 candidate interactions per head. A sparse graph with |E||E| edges has an edge-dependent propagation cost. Equal parameter counts therefore do not imply equal memory use, sequential depth, or runtime.

Check your understanding Is an encoder–decoder a competing layer type to an LSTM or Transformer?

No. Encoder and decoder describe roles in an input-to-output architecture. Either role can be implemented using recurrent layers, attention, convolutions, or other components. Autoencoder instead names a particular reconstruction objective with an encoder and decoder.
